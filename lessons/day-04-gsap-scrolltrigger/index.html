Day 4 · GSAP + ScrollTrigger

One sentence: scroll is a timeline. GSAP handles how things animate (readable, maintainable sequencing); ScrollTrigger handles when scroll drives it — scrub turns scroll position into animation progress, pin locks a section in place for multi-step storytelling. Scroll down and "play" each demo by hand. Each section has a ↻ replay button on the right.

01Scrub: the scrollbar is the playhead

Inside this 130vh zone, the bar's fill is bound to your scroll position — scroll up and it rewinds, stop and it freezes. That's scrub: scroll is no longer a trigger, it's the playhead. Below it, a Day-3-style toggle plays once on enter for comparison — two completely different semantics.

scrub progress 0% · scroll up/down, then stop

The number in scrub: 1 is smoothing in seconds — the animation trails the scroll by 1s, like inertia; scrub: true locks on frame-perfectly. For portfolios, 0.5–1 feels tactile without being dizzy.

02Pin: hold the screen, tell a story in steps

When you reach it, the stage gets pinned and the next 200% of scroll distance becomes a three-step animation: the two chips collide → the purple one spins and scales → the background shifts. This is the standard recipe for scroll-driven case studies: a timeline writes the steps, ScrollTrigger just maps scroll to time.

Notice: the scrollbar keeps moving while the frame stays put — GSAP inserts a pin-spacer that pads the document flow with "fake height". Layout suddenly getting longer is normal, not a bug.

03Parallax: foreground and background at different speeds

The glow and grid drift down slowly (yPercent: 15) while the headline rises fast (yPercent: -12) — your brain reads depth automatically. Parallax is just one trigger, different distances; scrub is what locks it to the scroll so tightly.

04Text reveal: light up word by word

Split the sentence into <span>s, then drive a stagger with scrub — scroll more, light more. The Awwwards-hero staple: the reader "reads" the sentence by scrolling, at their own pace.

A great portfolio lets the reader scroll through the story.

The minimal runnable code (all four moves)

<script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.5/gsap.min.js"></script>
<script src="https://cdnjs.cloudflare.com/ajax/libs/gsap/3.12.5/ScrollTrigger.min.js"></script>
<script>
gsap.registerPlugin(ScrollTrigger);

// 1. scrub: scroll position = animation progress
gsap.to('.bar', { scaleX: 1, ease: 'none',
  scrollTrigger: { trigger: '.stage', start: 'top 80%',
                   end: 'bottom 20%', scrub: 1 } });

// 2. pin + timeline: hold for 200% scroll, play in steps
const tl = gsap.timeline({ scrollTrigger: {
  trigger: '.story', start: 'top top',
  end: '+=200%', pin: true, scrub: 1 } });
tl.to('.card-a', { x: 300 })
  .to('.card-b', { rotation: 360 }, '<'); // '<' = at same time as previous

// 3. parallax: same trigger, different distances
gsap.to('.bg', { yPercent: 30, ease: 'none',
  scrollTrigger: { trigger: '.hero', start: 'top top',
                   end: 'bottom top', scrub: true } });

// 4. char-by-char reveal: split into spans + scrub stagger
el.innerHTML = el.textContent.split('').map(c => `<span>${c}</span>`).join('');
gsap.to(el.querySelectorAll('span'), { opacity: 1, ease: 'none', stagger: 0.05,
  scrollTrigger: { trigger: el, start: 'top 85%', end: 'bottom 45%', scrub: 1 } });

// 5. re-calibrate trigger positions after assets load (see gotcha)
window.addEventListener('load', () => ScrollTrigger.refresh());
</script>
✏️ Exercise — try it on your site. Open your portfolio draft portfolio-site-draft/index.html and give the hero a scroll narrative: (1) add the two GSAP CDN lines to <head>; (2) wrap the hero in .story with pin + scrub — reveal the headline char by char over 150vh (move 4) while a background glow parallaxes upward (move 3); (3) refresh and scroll slowly — if trigger positions feel "drifty" (animations early/late), add move 5's ScrollTrigger.refresh(). Don't panic when pin stretches the layout — that's the pin-spacer doing its job.
⚠️ Gotcha (the #1 beginner crash): trigger drift. Images and webfonts haven't loaded when ScrollTrigger measures the page, so every trigger point is computed against the wrong height — then everything drifts once they load. Build the habit: window.addEventListener('load', () => ScrollTrigger.refresh()), and refresh manually after any async content renders. While debugging, turn on markers: true — the trigger lines draw on screen and the problem is obvious.
💡 Portfolio cheat sheet: hero entrance choreography (timeline) → scroll narrative (pin + scrub to walk through a case) → parallax bands (hero/section dividers) → char-by-char reveals (manifesto copy). Four moves, and your 11/22 site has a scroll-storytelling skeleton.
