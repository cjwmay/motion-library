Day 3 · Scroll-triggered animation

One native tool does almost all of it: IntersectionObserver — the browser's built-in "element entered the viewport" sentinel, with zero scroll listeners and zero performance tax. Scroll down: each lab below animates itself. Play with them and lock in your site's reveal personality.

01Trigger timing: threshold

Same card, three threshold values — fires when 5% / 30% / 60% of the element is visible. The 60% one visibly lags; on a fast scroll it feels like it never caught up. For portfolios, 0.1–0.2 is the sweet spot — start the animation early.

03Stagger rhythm: how many ms feels right?

Same dot row, three gaps: 60ms ripples, 120ms feels composed, 240ms starts to drag. Implementation trick: each child gets a --d custom property and the shared transition reads transition-delay: var(--d). Choose your number — it becomes your site-wide stagger standard.

The copy-paste kit

<!-- HTML: .reveal on anything that should animate; data-stagger on groups -->
<h2 class="reveal">Case study title</h2>
<div class="reveal" data-stagger>
  <div class="card">…</div><div class="card">…</div><div class="card">…</div>
</div>

<style>
/* ⚠️ Initial hidden state lives under .js: no-JS users still see content */
.js .reveal { opacity: 0; transform: translateY(28px);
  transition: opacity .8s cubic-bezier(.22,1,.36,1),
              transform .8s cubic-bezier(.22,1,.36,1);
  transition-delay: var(--d, 0ms); }   /* stagger gap */
.js .reveal.in { opacity: 1; transform: none; }
</style>

<script>
document.documentElement.classList.add('js'); // hide only when JS runs

const io = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (e.isIntersecting) { e.target.classList.add('in'); io.unobserve(e.target); }
  });
}, { threshold: 0.15, rootMargin: '0px 0px -10% 0px' });

document.querySelectorAll('[data-stagger]').forEach(group =>
  [...group.children].forEach((c, i) => {
    c.classList.add('reveal');
    c.style.setProperty('--d', i * 100 + 'ms');
    io.observe(c);
  })
);
document.querySelectorAll('.reveal').forEach(el => io.observe(el));
</script>

Exercise

Add class="reveal" to every case-study section on your site, and data-stagger to card grids and feature lists. Use the stagger interval you picked in lab 03 — it is now your site-wide standard.

Pitfall

Never put opacity: 0 on the element or a plain class. Hide it only behind a .js flag that JavaScript itself adds on line one. If JS fails, errors, or gets blocked, a plain opacity: 0 turns your whole page into a blank page that "works fine in the code". Day 2's lesson was the transition in the wrong place; Day 3's is the initial state in the wrong place.
Tall blocks need low thresholds. A section taller than the viewport can never reach threshold: 0.5 — its animation never fires. Give tall sections threshold: 0.05 or their own observer.

Where to use it in your portfolio

  • Every case-study section → .reveal with the 01 rise pose
  • Feature lists / image grids → data-stagger at your chosen interval
  • Long pages → rootMargin head start so fast scrollers see the landing
  • Hero on load → same .in class, triggered by JS on page load instead of scroll
